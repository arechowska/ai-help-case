AI Help

A RAG assistant that answers users from the product documentation — in their own low-resource language, with a link to the source, and only from the documents of their own organisation.

I was the product owner in a team of three: requirements, the evaluation methodology and the testing itself, the glossary and translation workflow, materials. Colleagues built the platform and the translation pipeline. This page explains how we measured quality and what the numbers changed.

2026 Enterprise financial software Team of 3 Role: product owner, evaluation & testing RAG · LLM evaluation · machine translation

The problem

The user documentation exists in one language only. Users who speak another — a low-resource language with little training data for models — struggle to find and understand answers, so they go to support.

The question to answer: can an AI assistant close this gap — a question in the user’s own language, an answer with a link to the source, and never a document from another client?

What was built

Answers in the user’s language

Interface and answers in the target language, with a link to the source section.

Access by client and language

Each user sees only the documents of their own organisation, in their language.

Quality you can see

Answer rating and analytics built in, so quality is measured, not assumed.

Eight user guides were translated into the target language with machine translation guided by a glossary confirmed by a native speaker.

How it works

The evaluation methodology

The core of the project was not the assistant but the way to know whether it can be trusted.

Reference answers first

A set of questions with reference answers written before any run — plus questions the system had never seen and a sample of real user requests.

Repeated runs

Automated runs after every change, so each decision is compared on the same set.

Blind review

Two raters score answers without knowing the version, on an agreed scale: full, partial, wrong.

Access checks

Questions designed to pull another client’s documents.

What the numbers changed

Translate the documentation, not the conversation

Problem
Translating the question and the answer on the fly gave full answers in less than half of the cases.
Choice
Translate the documentation itself with a glossary and improve retrieval. Two weeks later: about 70% full answers on the first try.

Real requests are harder than invented ones

Problem
Real user requests scored noticeably lower than prepared questions.
Choice
Keep them in the set and report them separately — the gap is the honest picture of production.

Launch with a checkpoint, not everywhere at once

Problem
The production bar was not reached yet.
Choice
Recommend a launch for one client with a control point, instead of rounding the numbers up.

Results
