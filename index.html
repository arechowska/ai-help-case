AI Help

An assistant that answers users from product documentation in their own low-resource language, with a link to the source and only from their bank’s documents.

Role: product owner, evaluation and testing · Cross-functional team · Stack: RAG, LLM evaluation, machine translation

The problem

Documentation exists in one language. Users who speak another, a language with little training data for models, can’t find answers and go to support.

What was built

  • Answers in the user’s language, with a link to the source section.
  • Access by client and language: each user sees only their own bank’s documents.
  • Eight user guides translated with machine translation and a glossary confirmed by a native speaker.

How we measured

  • Reference answers written before any run.
  • Repeated runs after every change, on the same set.
  • Blind review by two raters: full, partial or wrong.
  • Questions designed to pull another client’s documents.

Key decisions

Translate the documentation, not the conversation

Problem
Translating the question and the answer on the fly gave full answers in less than half of the cases.
Choice
Translate the guides with a glossary and improve retrieval.

Real requests counted separately

Problem
Real user requests scored lower than the questions we prepared.
Choice
Keep them in the set and report them on their own.

Where it broke

  • Search in the user’s language found the wrong section far more often than in the source language.
  • Translation checks caught form, not meaning: a guide could pass every check and still say the wrong thing.

Results

  • ≈80%full answers in the user’s language after one follow-up question
  • 80%+full answers in the source language on the first try
  • 0answers from another client’s documents in access checks

Measured in repeated runs on different closed sets of questions, including real support tickets. Reference answers were written in advance; two raters scored answers blind.
